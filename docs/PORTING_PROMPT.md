Проект: реимплементация Neighbours from Hell (Android, Unity 5.3.4f1,
сезоны 1 и 2) на Python+PySDL2. Правила проекта — в `CLAUDE.md` и
`runtime/README.md`; они обязательны.

**Задача:** <фича / багфикс / подсистема>.

**Режим чтения — только целиком, без частичного.** Источник истины —
декомпилят `src/Assembly-CSharp` (193 файла, ~850 КБ ≈ 250k токенов —
целиком помещается в контекст; бюджет сессии это позволяет). Прежде чем
писать или менять хоть строку рантайма:

1. Прочитай через Read **полные файлы** всей затрагиваемой подсистемы —
   не grep-выдержки и не «окно вокруг строки». Ядро геймплея:
   `Item.cs` (2777 строк), `Pawn.cs` (1846), `HUD.cs` (1491),
   `TrickItem.cs` (1293), `Rottweiler.cs` (1292), `Woody.cs` (1189),
   `ActionManager.cs` (860), `RoutineActionUse.cs` (577),
   `GameInfo.cs` (542), `Door.cs`, `Alerter.cs`, `RoutineAction*.cs`,
   `Level.cs`, `CameraMover.cs`, `SearchItem.cs`, `HideItem.cs`,
   `Actor.cs`, `AnimationControllerBase.cs`, `Helpers.cs` — плюс каждый
   класс, на который читаемый код ссылается в рамках задачи. Если задача
   широкая или межсистемная — читай весь `src/` подряд.
2. grep разрешён только как оглавление (найти, какие файлы читать
   целиком), не как замена чтению.

**Реализация.** Каждая строка `runtime/` подкрепляется конкретным
методом оригинала со ссылкой `Файл.cs:строки` в комментарии. Расхождение
не затыкается эвристикой: либо чинится по коду, либо документируется в
`runtime/README.md` открытым вопросом с числами. Данные уровней
`levels/*.json` — тоже источник: перед реализацией ветки проверь, какие
уровни несут поле и с какими значениями; константы — из данных.

**Верификация.** Флаговых юнит-прогонов недостаточно — смотри кадры
глазами:

- `runtime/record.py` — детерминированная запись настоящего Viewer
  (фикс. 60 Гц, скриптовый ввод, кадры + `state.jsonl` на каждый тик);
- контактные листы: `ffmpeg -pattern_type glob -i 'f*.png'
  -filter_complex 'scale=200:150,tile=6x3' -frames:v 1 sheet.png`;
- сравнение с оригиналом: кадры референс-видео геймплея (yt-dlp с
  `--extractor-args "youtube:player_client=android"`, ffmpeg-нарезка:
  грубая сетка → мелкая → полнокадровый hstack бок-о-бок).

**Регрессия после каждого блока, до коммита:** рутинный свип всех
уровней (180 c симуляции, без исключений и «убеганий») + рендер-свип
(546/546 спрайтов, 0 потерянных листов). Коммиты — без AI-трейлеров.

**Известные грабли этого кодовой базы** (все уже стреляли; не повторяй):

- `RoutineActionUse.OnActionStarted` стреляет **по прибытии** пешки, а
  не при старте шага рутины (`ActionManager.StartAction` сначала
  вставляет `MoveAction`; шорткат `SameZone` — только urgent-пробежки к
  Dog/Chili).
- Сырой `Tricked` ≠ `IsTricked()`-цепь: гейты вида `if (Tricked)`
  читают сырое поле; цепь требует `DependsOn.Tricked && GotTricked`.
  `GotTricked` ставится в начале `RottweilerUse` независимо от наличия
  анимации.
- `this is TrickItem` в C# истинно и для наследников: Drawing, Rake,
  Toilet, Television.
- Пустая секвенция использования завершается мгновенно, но
  `StopAction`-флоу (angry-postpone) всё равно идёт — невидимые вентили
  L113 на этом держатся.
- Ссылки из данных — int, ключи JSON-объектов — строки: сравнение
  молча даёт False.
- Плоские имена текстур коллидируют (три ленты лиц несут `idle_0000`);
  `Resources.Load` разрешается через контейнер ResourceManager
  (class 147, путь→PPtr) — грузи по полным путям; в кэше каждый
  кандидат пробуется точно и без регистра **до** перехода к следующему
  (иначе basename затенит путь).
- Именные хаки (`name.Equals("...")`) — часть оригинала; портируются
  дословно, их инвентарь — `runtime/README.md`.
- Level.Start пересобирает зоны из списков Level-компонента;
  Woody.Start ставит его в `StartLocation` поверх LevelLocations;
  камера клампится в границы `CameraMover`.

Отчёт: что прочитано (файлы целиком), что реализовано (со ссылками),
чем проверено (записи/сравнения/свипы), что осталось открытым.
