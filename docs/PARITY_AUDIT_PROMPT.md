# Аудит паритета с оригиналом

Источник истины — декомпилят (`src/Assembly-CSharp`) **плюс контракты Unity-API,
которые он вызывает**. Задача — не новая фича, а систематический поиск
расхождений порта с оригиналом четырьмя проходами. Каждое найденное
расхождение либо чинится по коду (со ссылкой `File.cs:lines`), либо
документируется в `runtime/README.md` с числами.

Происхождение: три бага, пойманных игроком после полного портирования —
текст выше своей плашки (анкеровка `GUIStyle.m_Alignment` жила в движке, не
в декомпиляте), анимация удара выше пола (однострочный вызов
`MoveToEmptySpace` внутри портированного метода не был развёрнут), немой
курсор (`MouseOverIconName` нёс данные у ~20 предметов на уровень, но
подсистема была списана как «мобильный рудимент»). Каждый проход ниже
обобщает один из этих классов; четвёртый — страховка снизу.

## Проход 1: контракты движка

Декомпилят не содержит код Unity — всё, что порт реимплементирует «по памяти»,
подозрительно. Собери grep-ом по портированным подсистемам все вызовы
движка: `GUI.*`, `GUIStyle`, `Graphics.DrawTexture`, `GUIUtility.*`,
`Camera.*`, `Physics.Raycast`, `Input.*`, `Cursor.*`, `Time.*`, `Random.*`,
`Screen.*`, `Transform`, `Renderer`, `Resources.Load`. Для каждого выпиши
точный контракт движка — системы координат, якоря, дефолты, **какие
сериализованные поля потребляет сам движок, а не код игры** (у `GUIStyle` это
`m_Alignment`, `m_ContentOffset`, `m_Padding`, `m_WordWrap`, `m_TextClipping`;
у `GUI.matrix` — повороты; у `DrawTexture` — растяжение) — и сверь
реализацию порта с контрактом по полям. Правило: поле есть в экспорте,
порт его не читает, а потребитель — движок ⇒ это баг класса «текст выше
своего места». Выход: таблица API → контракт → где реализовано → сошлось/нет.

## Проход 2: замыкание графа вызовов

Для каждого портированного метода раскрой граф вызовов до листьев внутри
Assembly-CSharp. Каждый вызываемый метод обязан быть ровно одним из:
(а) портирован со ссылкой, (б) доказанно пуст/мёртв (показать), (в) внесён
в открытые вопросы. Механика: grep тел портированных методов на вызовы,
дифф со ссылками в комментариях порта. Особое внимание — однострочные
вызовы внутри уже портированных методов (класс `MoveToEmptySpace`: одна
строка меняет якорь всей анимации). Выход: список непройденных рёбер.

## Проход 3: данные без потребителя и «спящие» подсистемы

Перечисли все типы компонентов в сценах и все сериализованные поля с
не-дефолтными значениями по всем `levels/*.json`. Для каждого найди
потребителя в порте. Данные без потребителя = непортированное поведение
(класс `MouseOverIconName`: ~20 предметов на уровень несли имя курсора,
никто не читал). Запрещено списывать фичу как мёртвую из-за платформы:
декомпилят — Android-сборка (`IsMobileDevice()` всегда true), hover/курсор
на таче спят, но эталон — десктопный оригинал. Выход: таблица
поле → уровни/счётчики → потребитель или «непортировано».

## Проход 4: визуальная сверка якорей с эталоном

Автотесты проверяют «что произошло», этот проход — «где нарисовано».
Расширь `runtime/record.py`: симуляция мыши (каждый кадр вести курсор по
предметам/дверям/зонам, не парковать в (0,0)) и скрипты «интересных
моментов»: поимка с ударом, сон с баром, dexterity, пауза, тултипы с
предметом в руках и без, оба финала. Для каждого момента — скриншот порта
и парный кадр из видео прохождения оригинала (yt-dlp; грубая сетка →
точная), hstack. Сверять **якоря и позиции, не наличие**: текст внутри
плашки, hit-лист на линии пола, бар/заливка на своём смещении, иконка
курсора. Любое «выше/ниже/левее» — баг, фиксируется с числами (мировые
юниты / пиксели). Каждый пойманный класс превращается в повторяемую
проверку (скрипт момента + ассерт по `state.jsonl` или скриншоту).

## Отчёт

Что просканировано (счётчики по каждому проходу), что починено (со
ссылками), что задокументировано как расхождение с числами, что осталось
открытым. Регрессии перед коммитом: sweep всех уровней, behavior/sidefx
сьюты, render sweep, новые скрипты моментов.
