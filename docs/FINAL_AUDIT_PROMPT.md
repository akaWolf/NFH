# Финальный аудит: динамика, гонки, полнота

Источник истины — прежний: `src/Assembly-CSharp` плюс контракты движка.
Три статических прохода (контракты, граф вызовов, данные) и визуальная
сверка уже сделаны (`docs/audit/`, `runtime/README.md`). Они сверяли
*написанное*. Этот аудит сверяет *происходящее во времени* — и добивает
классы, которые статика ловит плохо.

Происхождение: баг «анимация двери играется второй раз» нашёл игрок, а не
аудит. Причина — пропущенная ЗАПИСЬ флага: `PlayDoorLeaveAnimation` ставит
`InputLocked = true` (Woody.cs:459-461), порт этого не делал, и клик посреди
прохода строил второй маршрут. Граф вызовов смотрел на вызовы, данные — на
поля, контракты — на формулы; никто не смотрел на **жизненный цикл флага**
и на **клик в неудачный момент**. Каждый проход ниже обобщает эту дыру.

## Проход 1: жизненный цикл каждого флага состояния

Перечисли ВСЕ bool/enum/ссылочные поля состояния в декомпиляте у Pawn,
Woody, Rottweiler, Mother, Olga, Kid, GameInfo, HUD, Item/TrickItem/
SearchItem/Door, ActionManager, AnimationControllerBase (`InputLocked`,
`Frozen`, `MovementPaused`, `IsWarping`, `Hiding`, `WasHiding`,
`AnimationsInProgress`, `PostponeAlert`, `ColoredTooltip`, `IsUsing`,
`GotTricked`, `WasPriming`, `IgnoreInfiniteLoop`, `PassingPawn`,
`UseDoorAtOnce`, `HasMouseInputStored`, `CanDecreaseAngryMeter`,
`ShouldStopAction`, `Tricked/Primed/Locked/FuckedUp`, ...— список собрать
grep-ом, не по памяти). Для каждого построй таблицу: **все места записи,
все места чтения, все гейты** — и сверь с портом строка в строку. Правила:

- пропущенная запись = баг класса `InputLocked` (дверная анимация дважды);
- пропущенное чтение = гейт, который в порте никогда не срабатывает;
- флаг, который в оригинале где-то сбрасывается, а в порте нет (или
  наоборот) = залипание; «ставится и не сбрасывается никогда» — допустимо
  только если так и в оригинале (пример: `TrickedAux`), с явной пометкой.

Выход: таблица флаг → записи/чтения (File.cs:строки) → порт → сошлось/нет.

## Проход 2: гонки ввода — обезьяна с инвариантами

Расширь `tests/`: детерминированная обезьяна поверх `runtime/record.py`
(фиксированный сид, 60 Гц) гоняет каждый уровень и целится кликами и
ховером **в моменты переходов**, а не в удобные паузы: клик во время
транзита двери, во время climb, в кадр вылезания из шкафа, во время
FearShort, во время использования предмета, в кадр поимки, во время
dexterity, на паузе, на скор-экране, в первую секунду входа, по два клика
в один тик, по HUD-кнопкам во время всего перечисленного. После КАЖДОГО
тика — инварианты (ассерты, падение = находка):

- не больше одного активного транзита на пешку; `is_warping` ⇒ спрайт
  скрыт и ввод заперт (для Woody);
- `input_locked`, `movement_paused`, `frozen`, `hiding`, `is_sleeping`,
  `colored_tooltip` не «залипают»: если флаг держится дольше N секунд без
  прогресса состояния — сигнал (N подбери по месту, зафиксируй);
- спрайт пешки не остаётся hidden вне транзита/пряток/избиения;
- рутина не стоит в `using/moving` без смены анимации дольше таймаута,
  кроме документированных вечных парковок (Level112 skates, мьютексы);
- координаты конечны и внутри зоны ± допуск; `current`-кадр в диапазоне
  листа; sequence-индексы в границах; инвентарь не уходит в минус;
- каждый начатый `stored_input` либо воспроизводится, либо явно
  сбрасывается (`ClearStoreBlockedInput`-места);
- часы стоят на паузе и идут вне её; angry-метр в [0, max].

Прогон: все 28 уровней × ≥3 минуты × ≥2 сида. Любое срабатывание
раскручивается до строки оригинала: либо порт чинится, либо инвариант
уточняется ссылкой на код.

## Проход 3: матрица трюков — каждый трюк каждого уровня до зачёта

Статика проверяла механизмы по отдельности; здесь — связки целиком. Для
каждого уровня составь план каждого трюка ИЗ ДАННЫХ (`SearchItem` →
инвентарь → `PrimingItem`/`PrimeWithInventory` → `RequiredInventory` →
цель; связки `LinkedItemTrick`, `DependsOn`, `RequirePriming`,
компаунды), запиши его скриптом момента (`tests/moments/` формат) и
прогони до конца: ассерты — трюк засчитан (`TrickScore` верной величины,
счётчик, линked-пары платят обе), сосед разозлился нужной веткой
(Classic/лестница NFH2), фикс происходит/`FuckedUp` по `CanFix`, повторный
клик даёт `WrongTrick`/пузырь как в коде. Недостижимый по данным трюк —
находка сама по себе (либо дыра порта, либо план требует ручного шага —
записать какого). Выход: 28 файлов планов + таблица трюк → статус.

## Проход 4: одноимённость и тихие дефолты

Два генератора багов, уже стрелявших (`ms_0000` — четыре разные текстуры
с одним именем; два разных `KidActions` — в ActionManager и в TrickItem):

- собери ВСЕ дубли имён: методы с одинаковой сигнатурой в разных классах,
  поля-тёзки (`Passable` у Item и у шага, `UseNormalSequence` у Kid и у
  TrickItem), ассеты с одним `m_Name` (текстуры, клипы, материалы). Для
  каждого дубля проверь, что порт ссылается на ПРАВИЛЬНОГО тёзку — по
  PPtr/классу-владельцу, не по имени;
- grep по порту всех `getattr(x, 'field', default)`, `d.get('Field') or
  default`, `spec.get(...) or ...`: каждый дефолт обязан совпадать с
  инициализатором поля в C# (пример ловушки: `AnimationInstance.FrameRate
  = -1f`, `Item.AngerAmount = 20`, `Item.Passable = true`) — а `getattr`
  с дефолтом, маскирующий отсутствие поля у целого класса, заменить на
  честное поле.

## Проход 5: покадровая численная сверка с эталоном

Прежняя сверка сравнивала якоря на избранных кадрах. Теперь — числа во
времени: из эталонного видео (мобильное прохождение, yt-dlp) вытащи
покадровый трекинг измеримых величин и сравни с `state.jsonl` того же
сценария: скорость ходьбы/бега Woody в экранных долях, длительность
транзита двери, длительность use-последовательности дивана, период лапа
рутины Level101, задержка старта рутин, время до музыки, длительность
Hello, тайминг бара сна до пробуждения. Допуск фиксируй числом (кадр
видео 30 fps ⇒ ±0.07 c) и записывай обе величины. Расхождение сверх
допуска — раскрутить до кода, а не подгонять допуск.

## Проход 6: обратный аудит порта

Правило проекта — каждая строка runtime/ подкреплена методом оригинала.
Пройди runtime/*.py в обратную сторону: найди все участки БЕЗ ссылки
`File.cs:строки` в комментарии рядом (грубый grep + чтение окрестностей).
Каждый такой участок — одно из: (а) добавить точную ссылку; (б) пометить
как решение вьюера/рекордера (follow-камера, печать состояния) в
комментарии; (в) признать изобретением — переписать по коду. Особо:
эвристики «почти как оригинал» (усреднения, «эквивалентно по результату»)
— перепроверить, что эквивалентность доказана в комментарии числами.

## Отчёт

Счётчики по каждому проходу (флагов сверено / инвариантов прогнано /
трюков зачтено / дублей проверено / величин сверено / строк без ссылок),
что починено (со ссылками), что задокументировано с числами, что осталось.
Регрессии перед коммитом: sweep всех уровней, render sweep, сьют моментов
(`tests/run_moments.py`), новая обезьяна с инвариантами и матрица трюков —
всё зелёное или расхождение объяснено строкой кода.
